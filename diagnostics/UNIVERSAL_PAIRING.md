# 通用配对与自动登记测试包

本包为新构建候选版，离线回归不等于实机验证。没有自动刷入设备，也没有清除任何配对。

## 本次更新

- 通用 BLE 键盘、鼠标：搜索后选中设备即可协商配对，不再额外选择某品牌的 Legacy 开关。优先 SC，允许选中设备协商旧式加密配对；仍要求加密及 16 字节密钥。键盘可能仍需按屏幕输入验证码。
- LisM：新左右手在尚未绑定时上报版本化角色。接收器可自动登记到空闲的一套，先左手后右手；不会替换已有角色。多个同侧候选同时出现时暂停，保留手动 Register。
- 自动登记先保存临时事务，连接加密且 split 服务初始化成功后才保存正式槽位。掉电可恢复；空闲失败约45秒或明确取消后，保留精确目标供手动登记重试，不删除其密钥。45秒是软超时，仍在连接中的慢设备可以继续完成；明确取消后不会再提交。若仍在连接中，先关闭这只新外设电源才能释放。未解决的恢复目标会暂停新自动登记，避免丢失地址线索。
- 保持原52字节配对记录格式，支持安全读取旧52和之前80字节记录；异常记录不自动删除，不在启动加载时迁移写入。没有第二份隐藏配对记录。
- 屏幕初始化时在亮屏前清空显存，避免暴露随机/残留像素。尚未实机证明此前花屏根因已完全消除。
- 电池供电期间维持低频、新鲜的电压观测；第二套右手slot5独立读取。此前两套右手插USB后曾丢失有效电量，随后复测两套均已成功显示插电闪电、拔电后继续显示电量；第一套仍有间歇失败历史。本包未改此判断，不宣称已彻底修好。不确定是否有电池时仍不显示闪电。未修改充电芯片控制、电压或充电电流。
- 第二套右手圆环及设备页直接读取实际六槽连接快照，避免漏到或陈旧的界面事件造成已连接却灰显；充电闪电仍必须有有效、未过期的充电证据。
- 两套外设新增独立、加密、只读的充电诊断通道；当USB已插入但电量未知时，dongle低频记录物理槽位、采样结果、电压、STAT脚、电池判断状态和开机时间。不发送控制命令，不改变原4字节电量协议；诊断读取失败不会清除原电量报告。此信息用于定位USB切换时证据丢失，不是已验证的充电修复。
- 在线但USB电量未知的外围圆环标注USB，与断连的“--”区分；不虚构百分比或闪电。
- 默认风格的横竖屏层名与下方层条选中态使用完全相同的白灰色#E0E0E0；`Bright`开启时的层名保持此前#B0B0B0，不随本次修改改变。设置页（第二页）的 `Bright` 配色开关默认关闭为灰调版，打开为提亮约30%版。这是配色，不是背光亮度。
- 灰调模式USB/BLE用上游原色；槽位选中数字黑色、其余灰紫色，避免亮白。提亮模式保留白色槽位数字。背景沿用原色系，彩色激活背景按同一有界30%规则切换；未激活的灰色背景不变。
- 电量绿色两档分别为#54806C与#6DA68C，圆环、设备页和本机电量条（含USB 100%）同步。橙色基值恢复上游#C08040；上游没有黄/红四档定义，这两档使用配套灰调#B4A264/#B77979，提亮模式在这些基值上增加约30%。切换配色不会改变电量阈值或充电识别。
- 打字玫瑰色和中性灰不随开关提亮；层名按上一条的两档固定色显示。切换不重建界面、不生成按键、不改配对。
- 选择使用独立显示设置保存，约2秒后写入；立即断电可能尚未保存。写入失败保留当前显示选择并有限重试，不影响输入或配对。配色仅由dongle负责；本次充电优化还需更新左右手，见下节。

诊断的 `uptime_s_mod65536` 每65536秒（约18.2小时）回绕，不能仅据该数字下降判断设备复位。

## 充电显示稳定性优化

- 本次重新编译dongle及左右手，两套键盘仍共用同一左手／同一右手UF2。新旧正常电量协议保持4字节v2，配对与充电芯片控制不变。
- 实测此前存在间歇灰显；现消除两类已确认程序缺陷，但尚不宣称实机根因完全解决：ADC/SOC测量结果不再与事件／BAS发送结果混为一谈；短暂失败不再无条件销毁仍在确认窗口内的电池信息。
- 对外遇到采样失败仍立即隐藏旧百分比及闪电。只有重新获得4次新鲜样本、跨度至少3秒才可恢复；不能拼接故障前的票数。
- USB切换的基线和7秒期限不可重试续期。已经正常报告的USB电池若发生短暂采样失败，只能从≤3.5秒前真实有效的最后样本建立新的恢复基线，并以该好样本时间为固定7秒起点；后续失败不能延长。重启、供电切换、越界、超过基线±80mV或明显跳变仍清除证据。
- 静态USB电压或STAT低电平本身不证明接了电池。保留原有≥150mV下降路径作为软件推断，因此并不承诺能绝对区分所有“未接电池／开关OFF／电池正在充电”状态；信息不足时仍显示USB，不虚构闪电。
- 加密诊断v2为18字节，默认MTU23可读取；dongle仍接受旧12字节v1。新诊断增加基线、最后失效原因、候选票数、固定种子年龄。失败不影响正常4字节电量报告。
- `last_reason`仅表示最近一次失效原因，不是当前充电硬件结论：0无记录、1采样失败、2电压越界、3跳变、4采样间隔过长、5超基线范围、6候选波动、7确认超时、8电源采样epoch变化、9无近期电池基线。

## 怎么更新

1. 屏幕dongle刷 `lism_dongle_xiao147_universal_pair_TEST.uf2`。
2. 两套左手均刷同一个 `lism_left_4waystick.uf2`；两套右手均刷同一个 `lism_right_trackball.uf2`。普通更新不刷reset，保留已登记设备和配对。
3. 已登记设备直接自动重连。还没有绑定过的左右手：dongle开机，先开左手，等待连接成功，再开右手；第一套全部关闭后再依次开启第二套。
4. 旧外设固件没有角色标签时，继续使用原手动Register。已经绑定其他dongle的键盘不能靠新固件自动接管；本包不会替你清除旧配对。

## 必须知道

- 角色广播用于设备归类，并不是密码学身份认证。首次登记时只给目标的一套上电。
- 不是“任何蓝牙设备”：仅标准BLE HID键鼠及已经支持的报告；不支持蓝牙Classic、专有多点触控协议或手柄输出。
- 安全策略不是macOS的完整复刻。仅对你选中或已保存的通用输入目标开放旧式配对，电脑和LisM split仍受SC限制，不自动覆盖更强密钥。
- 回退旧strict固件可能复用本包保存的真实central Legacy LTK；不宣称回退后仍保持旧版本的SC-only重连策略。
- 正常加密完成前不发现/订阅HID报告。去掉不需要的peripheral LTK持久副本会影响旧栈未加密GATT/L2CAP错误的分类，不影响本包先加密再发现HID的顺序。
- `reset_危险备用_默认不要刷` 会清除刷入目标的设置与配对，只是完整包备用，本次更新不要刷。

完整包保留JP19、CirclePad和reset；本次不需要重刷这三个文件。没有推送GitHub，实机构建结果与验证记录随包保存。
