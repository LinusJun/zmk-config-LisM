# CheerPod 限定兼容测试版

本版增加了按设备单独授权的旧式 BLE 配对兼容，用于尝试解决已确认的 `Secure Connections required (4)`。已编译及自动测试不等于 CheerPod 实机连接成功；尚需正常配对验证。

## 这次怎样刷和操作

1. 只刷本包 `lism_dongle_xiao147_input_receiver_TEST.uf2`（打包时替换为实际名称）。不要刷 reset，不需要重刷左右手或 G705。
2. 让 CheerPod 进入配对模式，进入 BLE Inputs，选择它所在的通用设备槽。更新不会保留上次未成功绑定的临时候选；若槽内为空，Search 后重新选择正确的 CheerPod。
3. 先按原安全方式 Retry／配对。只有确实因本地 Secure Connections 限制失败，才会出现可操作的 **Legacy** 按钮。
4. 点 Legacy，核对目标名称，阅读较弱配对安全性的提示，选 **Allow**，然后 Retry。USR1 仍是单击移动高亮、双击确认；警告页默认高亮 Cancel，防止连续按键误授权。
5. 看到 Ready 后测试移动、左右键和滚动。无需另开采样窗口。

兼容授权仅绑定所选设备的实际蓝牙身份，不按名称或槽位泛化。新候选、其他通用设备、分体键盘和电脑连接不继承该授权。即使允许兼容，仍广告并优先协商 Secure Connections，不主动改成旧协议。

成功连接并确认绑定后才保存授权，正常重启可重连。授权后的设备按钮显示 **SC only**，点击可关闭兼容并断开该设备，但保留它的旧配对。若提示保存失败，应重试 SC only，不把未成功保存的撤销当作已永久生效。

## 安全边界

旧式 BLE 配对比 Secure Connections 的防窃听能力弱，尤其首次配对时；本版仅实现用户明确选择的设备例外。保留原 16 字节最低密钥长度、MITM 配置和旧绑定防覆盖／防降级保护；这不表示所有无输入输出外设都能实现抗中间人认证。

身份解析必须对应同一连接和连接代次，并在访问旧身份密钥之前排除键盘、电脑和其他通用设备的身份；不通过删除其他绑定来绕开失败。

如果仍被密钥长度、认证或已有绑定保护拒绝，本版会保留明确提示，不自动继续放宽。只支持 BLE HID；此选项不是经典蓝牙支持，也不保证厂商私有触控协议或原生多点透传。

完整包中的外设与 reset 是原已核验版本，本轮只新编译 dongle。reset 单独放在危险备用目录，正常更新不要刷。此包未自动刷入设备，未清除任何配对，也未推送 GitHub。
