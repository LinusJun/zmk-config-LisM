# 通用 BLE HID 鼠标桥接实验版

本分支 `codex/cheerdots2-hid-bridge` 从已完成的 `e6fcd41` 稳定候选分离。
稳定分支 `codex/xiao147-display-fix` 不受影响。固件名称带 `hid_bridge_TEST`，
不是已验证的 Cheerdots2 完整兼容版，也不是原生多点触控板固件。

## 怎么配对

1. 仅将实验 UF2 刷到带屏 XIAO147 dongle。正常升级不刷 settings reset，
   不清除左右手键盘、摇杆或电脑的已有配对。
2. dongle 插电脑 USB，按 USR2 循环到第四页 **BLE Mouse (test)**。
3. 点 **Start scan (60s)**，再让鼠标或触控板进入自己的蓝牙配对模式。
4. 在屏幕选择对应设备。只有明确点选的设备才会建立新连接。
   搜索会列出可连接、且广播中声明 HID 类型的候选；未声明 HID 时，
   只对 G705、CheerPod/CheerPod2 等明确产品名或独立的 mouse/trackpad/touchpad
   名称词提供兼容兜底，不再把所有具名智能家居设备列出来。
   这些是**尚未验证的蓝牙设备**，不是都能作为鼠标使用。
   最多保留十二个候选，每页三行；用 **More** 翻页。列表满了或设备没显示，
   可取消后重新搜索。广播与扫描响应先合并后再筛选；无名 HID 仍可显示，
   已保存设备的精确地址重连不受此列表过滤影响。这不是 macOS 筛选策略的复刻，
   无 HID 声明且名称不符合这些提示的输入设备可能不显示。
5. 显示 **Ready** 后，测试移动、左右键、滚轮以及水平滚动。
   首轮优先通过 dongle 的 USB 输出测试；切换电脑／USB-BLE 输出前先
   松开鼠标按键。当前 ZMK 框架的 BLE 主机切换和无线传输失败场景仍需实测，
   不保证对已不可达的旧主机成功送达释放报告。
6. 成功验证的设备身份会保存，下次开机在收到该设备新广播后自动重连。
   **Forget mouse** 连点确认只遗忘这个鼠标，不删除键盘或电脑配对。

Cheerdots2 可用一个空闲蓝牙档位。若该档位正在连接另一台电脑，先断开
那个连接，再按设备说明进入配对状态；不要随意重置仍需保留的档位。

G705 测试时先拔掉鼠标充电线，底部连接键切到蓝牙，再长按约三秒，
确认蓝灯快速闪烁；暂时不要让 Mac mini 抢先连接。
[罗技官方配对说明](https://support.logi.com/hc/de/articles/7173630755863-How-do-I-connect-my-G705-using-Bluetooth)。
2026-10-17 已捕获 G705 的真实候选、连接与 Ready 日志，用户确认 USB 使用、
鼠标和 dongle 双方断电重连，以及 dongle 对 Mac 的 BLE 转发正常。
CheerPod 是另一台尚未连接成功的设备，不能用 G705 的通过结果代替其兼容验证。

## G705 扫描启动修复版

这一版修复已定位的初始化交接缺陷；不清除或迁移现有配对，
不修改蓝牙安全或自动重连策略。只刷本包内的 dongle UF2，
不要刷 settings reset，不必重刷外设。

此前 ee3c89e 诊断版的实机日志显示：Bluetooth ready、回调注册成功、搜索需求已生效，
但共享扫描器始终未启用，底层扫描启动调用为零。源码及最终初始化表核对发现，
替换源文件后，同优先级的 central 初始化早于 Bluetooth 初始化；central 先登记动态
设置处理器，随后 Bluetooth 首次初始化设置子系统时清空了这个内存登记链表。
这不是擦除了配对数据，但会使设置加载后的 central 启用通知丢失。

修复是在 central 登记之前先成功初始化设置子系统，再检查登记结果。
后续初始化具有幂等保护，不会再清掉登记；仍由原设置加载、transport manager
和启用回调启动唯一的共享扫描器，不直接强制 enabled，也不新增第二扫描器。
真实源码组合回归需覆盖旧顺序丢登记、两种修复后顺序、失败返回和重复初始化。

同时限定 Prospector 的连接观察器只处理真实 split 所有者，避免普通 HID 鼠标
写入键盘外设地址槽或产生无效 split 断线状态；保留真实 split 的原有观察功能。
扫描缺陷修复与编译通过本身不等于设备兼容验证；G705 的后续实机结果见上文。

新诊断分别记录扫描启动/停止的真实调用次数和返回值、提前返回的原因、
共享扫描器启用及扫描缓存状态、split 接收入口计数、HID 回调入口及门控后计数、
回调注册结果、Bluetooth ready 及设置加载/暂停/连接状态。
日志按搜索开始、约十秒间隔和结束输出；不逐包打印，不记录广播内容或按键输入。
累计计数需结合前后变化判断；未调用时的返回码不是“成功”，扫描缓存也不代表
控制器此刻确实在扫描。这些观测只用于诊断，不会自动触发扫描重启、断线或清配对。

刷好后保持 G705 未连接其他电脑并处于快闪配对状态，再接日志、点 Start scan，
让一整轮搜索自然结束即可。屏幕即使无候选也不要反复点；保留同一窗口的完整日志。

## 候选过滤与 CheerPod 连接诊断

默认候选过滤按正向输入设备提示，不使用 Aqara 品牌黑名单，也不会自动连接候选。
名称提示只允许设备出现在列表，绝不绕过连接后的 HID 服务和相对鼠标 Report Map 校验。
同一地址的近期名称/HID 提示会先合并；列表不按 RSSI 重排，选择 token 校验保持不变。

CheerPod 当前屏幕提示为 `Mouse disconnected; await advertisement`。这可能来自
连接完成回调失败，也可能来自已建立链路的断开，旧提示不能区分，不能据此认定
安全配对或 HID 解析就是根因。新日志记录所选名称、建连返回值/回调错误、断开原因、
安全等级/错误、HID 阶段、GATT/ATT 返回值、Report Map 解析结果和超时阶段。
这些记录只在协调线程输出，不记录鼠标输入数据或密钥，不修改安全等级、20 秒设置
总时限、重试、配对保存或清除策略；本版尚未解决或实机确认 CheerPod 的连接失败。

## 这一版支持范围

- 一台标准 BLE HOGP 外设，转发到 dongle 当前选择的 USB **或** BLE 电脑。
- 标准相对鼠标 X/Y、按钮 1–5、垂直 Wheel、水平 AC Pan。
- 如果触控板内部已把双指操作转为鼠标右键或滚轮，这些鼠标结果可转发。
- 不额外反转外设已处理的滚动方向；最终自然滚动还受电脑系统设置影响。
- 需要 PIN 或数字确认、仅经典蓝牙、仅专用 2.4G 接收器、未知厂商协议、
  键盘／媒体快捷键及原始 Digitizer 多触点不在首版转发范围。
- 不发送未知厂商 Feature 数据；仅做正常服务发现、加密配对、标准
  HID Report Mode 和通知订阅。
- 系统配对记录容量为十条。四个 split 外设、电脑与通用鼠标共用该容量，
  不自动覆盖旧配对；屏幕保留六个电脑配置档位，并不另增一套鼠标配对记录池。
  被判为不支持的设备可能已经在加密阶段创建系统 bond，
  但不会被保存为自动重连鼠标；首版不冒险自动删除这些无法完全确认归属
  的记录。反复试多种不支持设备可能耗尽配对槽，届时应先诊断记录，
  不要直接刷 reset 清空所有键盘和电脑配对。

## 安全与验证边界

解析器严格限制报告长度、字段、嵌套和报告数量。断线、取消、异常报告、
队列故障及切换电脑时取消本来源的按钮；不会用全局清空去释放其他来源
持有的鼠标键。扫描与 ZMK split 共用一个仲裁者，鼠标不占四个 split 槽。

自动测试覆盖完整模拟 GATT 流程、来源按钮计数、失效回调、取消和错误路径，
但模拟测试与编译成功不能证明真实设备配对、无线负载、Cheerdots2 多指兼容
或 Win10/11/macOS 原生系统手势已经通过。需要后续实机验证。
